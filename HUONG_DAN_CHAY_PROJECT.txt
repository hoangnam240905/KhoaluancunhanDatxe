==================================================
1. TỔNG QUAN REPOSITORY
--------------------------------------------------

Hệ thống cho thuê xe du lịch trực tuyến (đồ án CNTT-KLCN108).

Gồm:
- 1 Backend API (ASP.NET Core)
- 2 ứng dụng Flutter (CustomerApp, DriverApp)
- 4 website Razor Pages (PortalWeb, AdminWeb, CustomerWeb, DispatcherWeb)
- 1 thư mục script SQL Server (Database/) — không bắt buộc khi chạy mặc định

Phụ thuộc:
- Mọi app/web gọi Backend qua HTTP.
- Backend đọc database (mặc định SQLite file carrental.db).
- Website không kết nối database trực tiếp.
- CustomerApp và DriverApp không phụ thuộc nhau.
- Phải chạy Backend trước khi chạy app hoặc web.

Tối thiểu để demo:
Backend + (PortalWeb hoặc CustomerApp).

2.1. CHỨC NĂNG CỦA TỪNG THÀNH PHẦN
--------------------------------------------------
(Chỉ liệt kê chức năng có trong source. Không bịa.)

A) LUỒNG TỔNG

Người dùng
    ↓
PortalWeb  /  CustomerApp  /  DriverApp  /  (AdminWeb, CustomerWeb, DispatcherWeb — web riêng, không còn login riêng)
    ↓
Backend API  (http://localhost:5199)
    ↓
Database  (mặc định SQLite carrental.db)

Role (từ source):

Admin
    → PortalWeb /Account/Login (RoleRoutes.HomeFor → /Admin)
    → khu Admin trên PortalWeb (hoặc AdminWeb nếu đã có cookie riêng)

Dispatcher
    → PortalWeb /Account/Login (→ /Dispatcher)
    → khu Dispatcher trên PortalWeb (hoặc DispatcherWeb nếu đã có cookie riêng)

Customer
    → PortalWeb / CustomerApp / CustomerWeb
    → chức năng khách hàng

Driver
    → DriverApp, hoặc CustomerApp (RoleRouter case 'Driver' → DriverTripsScreen)
    → chức năng tài xế
    → KHÔNG có khu vực Driver trên PortalWeb (role khác Customer/Admin/Dispatcher → /Account/Login)

B) CUSTOMER APP  (CustomerApp/lib/)

Nguồn: screens/, services/api_service.dart, navigation/role_router.dart, data/portal_content.dart, models/, main.dart

Khách hàng (role Customer):
- Màn hình chờ / khôi phục phiên (SplashScreen, SharedPreferences)
- Đăng ký tài khoản (register_screen.dart → POST /api/auth/register)
- Đăng nhập (login_screen.dart → POST /api/auth/login)
- Đăng xuất
- Xem trang chủ: loại xe từ API, tuyến phổ biến / tính năng / bước đặt xe / FAQ tĩnh (portal_content.dart, không phải API)
- Xem thông tin loại xe (giá/ngày, giá/km, số chỗ) — getVehicleTypes(); KHÔNG gọi /api/vehicles
- Tạo đơn thuê xe (create_booking_screen.dart)
- Đặt theo tuyến phổ biến (điền sẵn điểm đón/trả, khoảng cách)
- Xem danh sách đơn thuê (bookings_screen.dart)
- Xem chi tiết đơn (bottom sheet: tuyến, thời gian, cước, ghi chú, tài xế/xe nếu đã phân công)
- Theo dõi trạng thái đơn (hiển thị field Status)
- RoleRouter: Admin/Dispatcher bị từ chối trên app

Tài xế trên cùng app (RoleRouter + driver_trips_screen.dart):
- Xem danh sách chuyến được phân công (GET /api/drivers/me/trips)
- Xem thông tin chuyến trên thẻ danh sách (không có màn hình chi tiết riêng)
- Nhận chuyến / Bắt đầu / Hoàn thành
- Cập nhật trạng thái tài xế: Available, Busy, Offline
- Đăng xuất

Không có trong CustomerApp source:
- Đánh giá chuyến/đơn (không có Review)
- Xem danh sách xe theo biển số (/api/vehicles)
- Thanh toán

C) DRIVER APP  (DriverApp/lib/)

Nguồn: screens/login_screen.dart, screens/trips_screen.dart, services/api_service.dart, main.dart

- Khôi phục phiên nếu role Driver còn hạn JWT
- Đăng nhập tài xế (chỉ chấp nhận role Driver)
- Đăng xuất
- Xem danh sách chuyến được phân công
- Xem thông tin chuyến trên danh sách (khách, tuyến, thời gian, trạng thái, biển số nếu có)
- Nhận chuyến (Assigned)
- Bắt đầu chuyến (Assigned hoặc InProgress)
- Hoàn thành chuyến (InProgress)
- Cập nhật trạng thái: Available / Busy / Offline

Không có trong DriverApp source:
- Đăng ký
- Đặt xe / xem loại xe
- Đánh giá

D) PORTAL WEB  (cổng đăng nhập web duy nhất — :5180)

Nguồn: Pages/, Services/CarRentalApiClient.cs, Services/AuthSession.cs (RoleRoutes), Program.cs

AUTHENTICATION:
- Đăng nhập chung (Pages/Account/Login → POST /api/auth/login)
- Đăng ký khách hàng (Pages/Account/Register → POST /api/auth/register)
- Đăng xuất
- Role routing: Admin → /Admin, Dispatcher → /Dispatcher, Customer → /, khác → /Account/Login
- Cookie: CarRentalPortalAuth (không chia sẻ với AdminWeb/CustomerWeb/DispatcherWeb)

CUSTOMER:
- Trang chủ: loại xe từ API; tuyến phổ biến, tính năng, bước đặt, FAQ tĩnh (PortalContent)
- Đặt xe (Pages/Customer/Bookings/Create)
- Xem danh sách + chi tiết đơn trên cùng trang (tuyến, thời gian, cước, tài xế/xe nếu đã gán)
- /Customer/Index chỉ redirect /#bang-gia
- Không có trang Đánh giá trên PortalWeb (CarRentalApiClient có CreateReviewAsync nhưng không có Page gọi)

ADMIN:
- Dashboard: đếm xe, tổng đơn, đơn Pending
- Danh sách / thêm / sửa / xóa xe
- Xem đơn (lọc status query)
- Hủy đơn (PATCH status Cancelled)

DISPATCHER:
- Xem đơn Pending và Confirmed
- Xác nhận đơn (POST /api/dispatch/bookings/{id}/confirm)
- Phân công tài xế + xe (Assign: DriverId, VehicleId; danh sách driver/xe Available)

Driver: không có khu vực web trên PortalWeb.

E) ADMIN WEB  (:5258) — web Admin riêng

Nguồn: Pages/Index, Pages/Vehicles/*, Pages/Bookings/Index, Pages/Account/Logout
- KHÔNG còn trang Login riêng (đã xóa Pages/Account/Login.*)
- Chưa đăng nhập → redirect http://localhost:5180/Account/Login
- Cookie riêng CarRentalAdminAuth (đăng nhập PortalWeb không tự login site này)
- Đăng xuất (xóa cookie local, rồi chuyển PortalWeb login)
- Dashboard: số xe, số đơn, số Pending
- Quản lý xe: danh sách, thêm, sửa, xóa
- Xem đơn; hủy đơn (Cancelled)

F) DISPATCHER WEB  (:5206) — web điều phối riêng

Nguồn: Pages/Index, Pages/Assign, Pages/Account/Logout
- KHÔNG còn Login riêng; chưa login → http://localhost:5180/Account/Login
- Cookie riêng CarRentalDispatcherAuth
- Đăng xuất → PortalWeb login
- Xem đơn Pending; xác nhận đơn
- Xem đơn Confirmed; phân công tài xế + xe

G) CUSTOMER WEB  (:5162) — web khách hàng riêng

Nguồn: Pages/Index, Pages/Bookings/*, Pages/Account/Register, Pages/Account/Logout
- KHÔNG còn Login riêng; link/redirect login → http://localhost:5180/Account/Login
- Register vẫn còn (Pages/Account/Register): đăng ký rồi ghi cookie local CarRentalAuth
- Đăng xuất → trang chủ CustomerWeb
- Trang chủ: xem loại xe + giá (API vehicle-types)
- Đặt xe; xem danh sách đơn
- Đánh giá đơn khi Status == Completed (Pages/Bookings/Review)

H) BACKEND / API

Nguồn: Controllers/, Services/

AUTH:
- Đăng nhập JWT (POST /api/auth/login)
- Đăng ký khách hàng (POST /api/auth/register)
- Lấy hồ sơ người dùng hiện tại (GET /api/auth/me) — có trong AuthController; không thấy app/web nào gọi trong source

VEHICLES:
- Xem loại xe (GET /api/vehicle-types, public)
- Xem danh sách xe / chi tiết xe (GET /api/vehicles, GET /api/vehicles/{id}, public)
- Thêm / sửa / xóa xe (Admin)

Không có API tạo/sửa/xóa loại xe.

BOOKINGS:
- Tạo đơn (Customer)
- Xem danh sách / chi tiết đơn (Customer thấy đơn mình; Admin/Dispatcher thấy tất cả)
- Cập nhật trạng thái đơn (Admin, Dispatcher — PATCH /api/bookings/{id}/status)
- Đánh giá đơn (Customer — POST /api/bookings/{id}/reviews)

DISPATCH:
- Xác nhận đơn
- Phân công tài xế + xe

DRIVERS:
- Danh sách tài xế (Admin, Dispatcher)
- Chuyến của tài xế đang đăng nhập
- Cập nhật trạng thái tài xế
- Nhận / bắt đầu / hoàn thành chuyến

Không có PaymentsController. Bảng Payments có trong DB/Entities/DbSeeder; không có API thanh toán.

I) DATABASE

Nguồn: Backend/Entities, Backend/Data/CarRentalDbContext.cs, Database/02_CreateTables.sql, DbSeeder.cs

Có:
- Roles, Users (tài khoản)
- Customers, Drivers
- VehicleTypes, Vehicles
- Bookings
- TripAssignments (phân công tài xế + xe cho đơn)
- BookingStatusHistory
- Payments (lưu/seed; không có API)
- Reviews

Không có trong source:
- RefreshToken
- DriverVehicle (quan hệ xe-tài xế nằm ở TripAssignments)

16. CÁC LỖI THƯỜNG GẶP
--------------------------------------------------

Chỉ ghi lỗi liên quan đến project thực tế.

1) flutter pub get thất bại
   Nguyên nhân: chưa cài Flutter, hoặc Dart < 3.11.1 (pubspec yêu cầu sdk: ^3.11.1)
   Xử lý: cài Flutter, chạy `flutter doctor`, kiểm tra `dart --version`

2) flutter run không thấy Android device
   Nguyên nhân: chưa bật emulator / chưa cắm điện thoại
   Xử lý:
     flutter devices
     Android Studio → Device Manager → Start emulator
   Ghi chú: máy kiểm tra file này có Windows/Chrome/Edge, chưa có Android emulator.

3) App không gọi được API (Android Emulator)
   Nguyên nhân: Backend chưa chạy, hoặc đã đổi baseUrl thành localhost
   Xử lý: chạy Backend port 5199; giữ baseUrl = http://10.0.2.2:5199

4) App không gọi được API (Chrome / Windows)
   Nguyên nhân: baseUrl đang là 10.0.2.2 (chỉ đúng cho Android Emulator)
   Xử lý: sửa api_config.dart thành http://localhost:5199

5) App trên điện thoại thật không gọi được API
   Nguyên nhân: 10.0.2.2 không phải IP máy thật
   Xử lý: đổi baseUrl thành http://<IP-LAN-máy-Backend>:5199
          cùng Wi-Fi; tường lửa Windows cho phép port 5199

6) Port 5199 bị chiếm
   Nguyên nhân: Backend cũ còn chạy, hoặc process khác dùng 5199
   Xử lý: đóng process cũ, hoặc đổi Urls rồi cập nhật mọi ApiBaseUrl/baseUrl

7) dotnet run / restore lỗi thiếu SDK
   Nguyên nhân: chưa cài .NET 10 SDK (csproj TargetFramework = net10.0)
   Xử lý: cài .NET 10 SDK, kiểm tra `dotnet --version`

8) Web chạy nhưng không load dữ liệu
   Nguyên nhân: Backend chưa chạy, hoặc ApiBaseUrl sai
   Xử lý: chạy Backend trước; giữ ApiBaseUrl = http://localhost:5199

9) Database SQLite không tạo
   Nguyên nhân: Backend crash trước EnsureCreated, hoặc không quyền ghi thư mục
   Xử lý: chạy `dotnet run` từ thư mục Backend, xem log
          Không cần tạo file .db thủ công

10) Chuyển SQL Server thất bại
    Nguyên nhân: vẫn để DatabaseProvider = Sqlite; connection string sai;
                 chưa chạy script Database/
    Xử lý: chỉ làm nếu thật sự cần SQL Server.
           Chạy 01 → 02 → 03. Sửa DatabaseProvider = SqlServer và DefaultConnection.

11) Flutter Android build lỗi Gradle / CMake / file lock (Windows)
    Nguyên nhân: antivirus khóa file build (repo đã có script)
    Xử lý (chỉ CustomerApp):
      cd CustomerApp
      powershell -ExecutionPolicy Bypass -File .\run_android.ps1
    Hoặc:
      powershell -ExecutionPolicy Bypass -File .\setup_build_junction.ps1

12) CustomerApp cài lên điện thoại ARM thất bại
    Nguyên nhân: android/app/build.gradle.kts có abiFilters.add("x86_64")
    Xử lý: dùng emulator x86_64, hoặc sửa abiFilters cho đúng kiến trúc máy
           (cấu hình Android hiện tại, không phải lỗi Flutter SDK)

13) flutter clean khi build hỏng
      cd CustomerApp
      flutter clean
      flutter pub get
      flutter run
    Làm tương tự với DriverApp.

14) HTTPS redirection
    Backend/Program.cs có app.UseHttpsRedirection()
    Client đang dùng http://localhost:5199
    Nếu gặp redirect/SSL: dùng URL HTTP port 5199 như cấu hình hiện tại.

15) dotnet restore Backend cảnh báo NU1903
    Đã quan sát khi restore Backend: warning Microsoft.OpenApi (gói kéo theo OpenApi 10.0.3)
    Restore vẫn thành công (exit code 0). Không chặn chạy.
    Không tự ý đổi package version trừ khi được giao.
